# Навык локализации проектов (i18n-helper)

Этот навык предназначен для полного цикла интернационализации (i18n) и локализации (l10n) проектов любого стека: React, Vue, Svelte, Angular, Flutter, iOS, Android, Python, Go, Node.js.

## 1. Этапы локализации проекта

### Шаг 1: Аудит и обнаружение хардкода
1. Поиск текстовых литералов в JSX/TSX/HTML/шаблонах с помощью регулярных выражений или AST-анализа.
2. Исключение системных строк: ключи словарей, имена атрибутов, CSS-классы, regex, пути к файлам.
3. Составление таблицы найденных пользовательских строк.

### Шаг 2: Выбор или интеграция i18n фреймворка
- **React / Next.js**: `i18next`, `react-i18next`, `next-intl`
- **Vue / Nuxt**: `vue-i18n`, `@nuxtjs/i18n`
- **Flutter**: `intl`, `.arb` файлы (`flutter_localizations`)
- **iOS (Swift)**: `String Catalog` (`.xcstrings`), `NSLocalizedString`
- **Android**: `res/values/strings.xml`, `res/values-ru/strings.xml`
- **Python / Django / FastAPI**: `gettext`, `Babel`, `django.utils.translation`
- **Electron / Vanilla JS**: JSON словари с `Map` и MutationObserver / contextBridge.

### Шаг 3: Генерация словарей переводов
1. Использование осмысленных ключей (например, `auth.login_button` вместо `button_1`).
2. Поддержка плюрализации (1 день, 2 дня, 5 дней) с учетом русской грамматики (`one`, `few`, `many`, `other`).
3. Поддержка интерполяции переменных (например: `Привет, {{name}}!`).

### Шаг 4: Проверка и тестирование
1. Убедиться, что при переключении языка не ломается разметка (flex/grid контейнеры, длина строк на русском обычно на 15-30% длиннее английских).
2. Проверить плейсхолдеры в инпутах, подсказки (tooltips), сообщения валидации форм и системные уведомления.
